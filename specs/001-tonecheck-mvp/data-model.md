# Data Model: ToneCheck Browser Extension MVP

**Date**: 2025-01-21  
**Phase**: 1 - Design & Contracts

## Overview

ToneCheck uses minimal persistent data storage, following privacy-by-design principles. Most data is ephemeral (in-memory only) and cleared after analysis completes. Only user settings and encrypted API keys are persisted.

## Entities

### 1. Text Analysis Request (Ephemeral)

**Purpose**: Represents a request to analyze text tone. Does not persist after analysis completes.

**Fields**:
- `text`: string (required) - The text content to analyze
- `timestamp`: number (required) - Unix timestamp when request was created
- `fieldId`: string (required) - Unique identifier for the target text field (DOM element ID or generated UUID)
- `url`: string (required) - URL of the page where text field is located
- `requestId`: string (required) - Unique identifier for this analysis request (UUID)

**Validation Rules**:
- `text` must be non-empty string
- `text` length must be <= 20,000 characters (Perspective API limit)
- `fieldId` must be non-empty string
- `url` must be valid URL format

**State Transitions**: None (ephemeral, deleted after analysis)

**Storage**: In-memory only (not persisted to browser.storage)

---

### 2. Tone Analysis Result (Ephemeral)

**Purpose**: Represents the output of tone analysis from Perspective API.

**Fields**:
- `requestId`: string (required) - Reference to the original analysis request
- `toxicity`: number (required) - Toxicity score (0.0-1.0)
- `severeToxicity`: number (required) - Severe toxicity score (0.0-1.0)
- `identityAttack`: number (required) - Identity attack score (0.0-1.0)
- `insult`: number (required) - Insult score (0.0-1.0)
- `profanity`: number (required) - Profanity score (0.0-1.0)
- `threat`: number (required) - Threat score (0.0-1.0)
- `overallAggression`: number (required) - Calculated overall aggression percentage (0-100)
- `timestamp`: number (required) - Unix timestamp when analysis completed
- `fieldId`: string (required) - Reference to the analyzed text field

**Validation Rules**:
- All score fields must be numbers between 0.0 and 1.0
- `overallAggression` must be calculated as: `max(toxicity, insult, threat) * 100`
- `requestId` must match a valid analysis request

**State Transitions**: None (ephemeral, deleted after UI display)

**Storage**: In-memory only, cleared after user dismisses warning or sends message

---

### 3. User Settings (Persistent)

**Purpose**: Stores user preferences and configuration. Persisted in `browser.storage.local`.

**Fields**:
- `apiKeyToneAnalysis`: string (optional) - Encrypted API key for Perspective API
- `apiKeySuggestions`: string (optional) - Encrypted API key for suggestion service (Claude or Gemini)
- `suggestionProvider`: string (required, default: "gemini") - Suggestion service provider: "claude" | "gemini"
- `sensitivityThreshold`: string (required, default: "medium") - Sensitivity level: "low" | "medium" | "high"
- `disabledWebsites`: string[] (required, default: []) - Array of website domains where extension is disabled
- `extensionEnabled`: boolean (required, default: true) - Global enable/disable toggle
- `lastUpdated`: number (required) - Unix timestamp of last settings update

**Validation Rules**:
- `sensitivityThreshold` must be one of: "low", "medium", "high"
- `suggestionProvider` must be one of: "claude", "gemini"
- `disabledWebsites` must be array of valid domain strings (e.g., "gmail.com", "reddit.com")
- `apiKeyToneAnalysis` and `apiKeySuggestions` must be encrypted before storage
- `extensionEnabled` must be boolean
- If `suggestionProvider` is "claude", `apiKeySuggestions` should be a Claude API key
- If `suggestionProvider` is "gemini", `apiKeySuggestions` should be a Gemini API key

**Sensitivity Threshold Mappings**:
- `low`: Aggression threshold 70%+ (only flag highly aggressive content)
- `medium`: Aggression threshold 50%+ (default, balanced)
- `high`: Aggression threshold 30%+ (flag even mildly concerning content)

**State Transitions**:
- Settings can be updated via popup or options page
- Changes take effect immediately (no restart required)
- API keys can be added/removed/updated

**Storage**: `browser.storage.local` (encrypted API keys)

**Encryption**: API keys are encrypted using Web Crypto API before storage, decrypted only when needed for API calls

---

### 4. Alternative Suggestion (Ephemeral)

**Purpose**: Represents a suggested text replacement generated by Claude API or Gemini API.

**Fields**:
- `originalText`: string (required) - The original flagged text segment
- `suggestion`: string (required) - The alternative phrasing
- `confidence`: number (optional) - Quality/confidence indicator (0.0-1.0) if provided by API
- `requestId`: string (required) - Reference to the tone analysis result that triggered this suggestion
- `timestamp`: number (required) - Unix timestamp when suggestion was generated

**Validation Rules**:
- `originalText` and `suggestion` must be non-empty strings
- `suggestion` must differ from `originalText`
- `confidence` (if present) must be between 0.0 and 1.0

**State Transitions**: None (ephemeral, deleted after user accepts/dismisses)

**Storage**: In-memory only, cleared after user accepts suggestion or dismisses warning

---

## Relationships

```
Text Analysis Request (1) ──→ (1) Tone Analysis Result
Tone Analysis Result (1) ──→ (0..3) Alternative Suggestion
User Settings (1) ──→ (controls) Text Analysis Request
```

**Notes**:
- One analysis request produces one result
- One result can trigger 0-3 alternative suggestions (if flagged as problematic)
- User settings control whether analysis requests are created

---

## Data Flow

### Analysis Flow
1. User types in text field → Content script detects input
2. After 500ms debounce → Create `Text Analysis Request` (in-memory)
3. Background worker receives request → Call Perspective API
4. API response → Create `Tone Analysis Result` (in-memory)
5. If aggression > threshold → Generate `Alternative Suggestion`(s) via Claude API
6. Display results in UI → User accepts/dismisses
7. Clear all ephemeral data from memory

### Settings Flow
1. User opens popup/options page → Load `User Settings` from `browser.storage.local`
2. User updates settings → Encrypt API keys if provided
3. Save to `browser.storage.local` → Update `lastUpdated` timestamp
4. Settings take effect immediately for new analysis requests

---

## Privacy Considerations

- **No persistent text storage**: All text analysis requests and results are in-memory only
- **Encrypted API keys**: User API keys are encrypted before storage using Web Crypto API
- **No telemetry**: No user behavior tracking or analytics data stored
- **Temporary caching**: API responses may be cached in-memory for <5 seconds to reduce redundant calls, then cleared
- **Clear on navigation**: All ephemeral data is cleared when user navigates away from page

## Storage Schema

### browser.storage.local Structure

```typescript
{
  "userSettings": {
    "apiKeyToneAnalysis": "encrypted_string",  // Encrypted Perspective API key
    "apiKeySuggestions": "encrypted_string",    // Encrypted Claude or Gemini API key
    "suggestionProvider": "gemini",             // "claude" or "gemini"
    "sensitivityThreshold": "medium",
    "disabledWebsites": ["example.com"],
    "extensionEnabled": true,
    "lastUpdated": 1705852800000
  }
}
```

**Storage Keys**:
- `userSettings`: UserSettings object (single key for all settings)

**No other persistent storage** - all other data is ephemeral/in-memory.
